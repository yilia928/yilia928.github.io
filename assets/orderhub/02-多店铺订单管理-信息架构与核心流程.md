## 1. MVP 信息架构（5 大模块）

```
多店铺订单管理（MVP）· Web 端
│
├── 1 仪表盘
│     ├── 订单总览（今日订单 / 待处理 / 异常数）
│     ├── 库存预警卡片
│     ├── 对账提醒
│     └── 快捷入口
│
├── 2 订单中心（核心模块）
│     ├── 订单列表：多平台聚合 / 筛选 / 搜索
│     ├── 订单详情
│     ├── 批量操作：审核 / 分配仓库 / 打单 / 发货 / 回传单号
│     └── 异常订单（缺货 / 地址异常 / 退款）
│
├── 3 库存管理
│     ├── 跨店库存总览（可售量 / 在途）
│     ├── 超卖预警（低库存商品列表）
│     └── 库存调整记录
│
├── 4 对账中心
│     ├── 平台结算单列表
│     ├── 订单-结算核对（差异标记）
│     └── 费用明细
│
└── 5 店铺管理
      ├── 店铺授权（Shopee / Lazada / TikTok Shop）
      ├── 发货规则（默认仓库 / 面单格式）
      └── 成员与权限（预留）
```

## 2. 原型页面清单（6 页）

| 页面 | 核心功能点 | 优先级 |
|---|---|---|
| 仪表盘页 | 今日订单 / 待处理 / 异常数、库存预警卡片、对账提醒、快捷入口 | P0 |
| 订单列表页 | 多平台订单聚合、按平台 / 状态 / 时间筛选、批量选择、批量发货入口 | P0 |
| 订单详情页 | 订单与买家信息、商品明细、物流跟踪、操作记录、异常处理 | P0 |
| 批量发货页 | 选择仓库、批量打单、面单预览、批量回传单号 | P0 |
| 库存预警页 | 低库存 / 超卖风险商品列表、一键调拨或下架建议 | P1 |
| 对账中心页 | 平台结算单列表、订单-结算核对、差异标记、费用明细 | P1 |

> 原型顺序建议：订单列表 → 订单详情 → 批量发货（3 个关键页先画）→ 仪表盘 → 库存预警 → 对账中心。

## 3. 核心流程

### 流程 A · 正向订单处理流

```
订单同步（3 平台）→ 订单审核 → 分配仓库 → 批量打单 → 拣货发货 → 回传单号 → 平台确认 → 完成
```

异常分支：
- 审核时地址异常 → 拦截订单 / 联系买家
- 平台取消订单 → 同步状态并释放库存

### 流程 B · 异常缺货流（超卖预警）

```
发货前库存不足 → 系统超卖预警 → 卖家处理（调拨库存 / 取消订单 / 联系买家换货）→ 通知买家 → 订单状态更新
```

预警触发条件：跨店可售量 < 在途订单量（含直播 / 大促等爆单场景）

## 4. 本阶段设计备注（可写进 PRD 的思考）

1. **为什么订单中心是核心模块**：直接对应用户最高频操作（每天 2-3 小时处理订单），也是效率提升（北极星指标：百单处理耗时）的主战场。
2. **批量发货页单独成页**：打单、贴单是单量上升后的第一瓶颈，需要专门优化操作路径。
3. **超卖预警是差异化卖点**：竞品 BigSeller 以「防超卖」为核心卖点 [1]，预警页的交互深度（触发条件、处理动作）决定产品口碑。
4. **对账中心 MVP 只做简化版**：先解决「能不能对上」，再迭代「为什么对不上」（费用明细深度拆解）。
