## 2. 关键设计决策（面试可讲的"为什么"）

1. **异常订单行高亮 + 预警条**：超卖是跨境卖家最高发风险 [1]，把异常前置到列表和详情两级，让卖家"先处理异常、再批量发货"，对应超卖率下降 50%+ 的目标。
2. **批量发货独立成页并带步骤条**：打单/贴单是单量上升后的第一瓶颈，用「选仓→选渠道→打面单→回传单号」四步把复杂操作拆成低认知负担的流程。
3. **平台 Tab 带计数**：卖家对"哪个平台单多"有强感知，Tab 计数既是筛选也是经营视图。
4. **订单详情物流区提示平台时效规则**（48 小时首条物流信息）[2]：把平台合规规则内嵌到操作上下文，降低卖家踩坑率——这是 B 端产品"懂业务"的体现。
5. **MVP 边界克制**：只做 Web 端、只覆盖订单核心链路，不进销存、不做商品刊登，避免与 BigSeller 等全功能 ERP 正面竞争 [3]。

## 3. 原型说明（交付须知）

- 打开方式：浏览器直接打开 `原型/index.html`；通过顶部页面按钮或 URL hash（#orders / #detail / #ship）切换视图。
- 已实现：列表筛选、搜索、勾选、批量条、详情联动、打单进度模拟、toast 反馈。
- 未实现（演示占位）：导出、批量审核、调拨/取消订单、真实数据接口、多语言切换——点击会给出"演示环境"提示。
- 示例数据：10 条订单为演示截取，全天场景值 128 单/23 待处理/5 异常为产品设定口径。
