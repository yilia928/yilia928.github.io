版本：V1.0 状态：评审稿 作者：产品团队（逆向设计项目） 日期：2026-09-17 参照对象：纷享销客 / 销售易

1. 文档概述

1.1 背景与目标

本项目以纷享销客、销售易两款主流 CRM SaaS 为参照，逆向拆解其客户管理链路，完成一套可落地的「客户与商机管理后台」设计方案。核心目标：

  • 梳理「线索 → 商机 → 合同 → 回款」主流程与状态流转规则；
  • 设计销售 / 销售主管 / 区域总监三级数据权限体系（本人 / 本团队 / 本区域）；
  • 输出核心页面高保真原型（HTML 版，等效 Axure RP 交互稿）；
  • 形成本标准化 PRD 文档；
  • 建立客户全生命周期指标方案（线索转化率、赢单周期、跟进及时率等）。

1.2 目标用户与核心痛点

销售主管过程可见、风险前置；公平分配线索漏斗靠口头汇报，超期跟进无预警，折扣审批无据

2. 竞品逆向拆解

2.1 拆解结论

维度纷享销客销售易本项目取舍
流程体系连接型 CRM，微信沟通记录自动同步、外勤签到/拜访报告完善LTC 端到端：MTL→LTO→CPQ→OTC 四环节打通采用销售易的 LTC 主干，吸收纷享的外勤跟进与公海机制
公海/线索池规则丰富：超期掉落、冷却期、领取上限偏企业自定义，配置门槛高预置 7 天/30 天掉落 + 15 天冷却，规则可配
商机管理阶段自定义 + 门禁校验阶段赢单率与预测联动阶段门禁 + 赢单率加权预测两者都要
权限体系组织树 + 数据范围（本人/团队/部门）+ 字段级角色权限矩阵清晰，审计完善三级角色 + 数据范围 + 字段级脱敏 + 审计日志

2.2 逆向出的关键设计原则

  • 先流程后功能：所有页面挂接在 LTC 主流程节点上，无孤立功能；
  • 录入减负：查重前置、必填最小化（线索 4 字段可创建）、跟进支持语音/拍照；
  • 过程数据资产化：每次跟进自动沉淀时间线，主管可回放；
  • 权限即数据：数据范围在 SQL 层过滤（owner / team / region），而非前端隐藏。

3. 业务流程与状态流转

本章完整图示见交付物《业务建模图集.html》（图 1 泳道流程 / 图 2 四对象状态机 / 图 3 信息架构）。此处仅摘录规则要点。

3.1 主流程

线索获取与查重 → 分配/领取 → 跟进验证 → 转化（客户+商机） → 商机阶段推进（门禁） → 报价/合同审批 → 签订生成回款计划 → 回款核销 → 复购增购回到商机。

3.2 状态流转规则要点

对象状态集关键规则
线索待分配 → 跟进中 → 已转化 / 无效 / 公海24h 首访红线；7 天未跟进掉公海；无效为终态需原因；转化原子性生成客户+商机
商机初步接触(15%) → 需求确认(30%) → 方案报价(45%) → 商务谈判(75%) → 赢单/输单门禁校验（POC/报价单）；反向回退需审批；停留阈值告警；输单原因+竞对必填；加权预测=金额×赢率
合同草稿 → 审批中 → 已签订/已驳回 → 执行中 → 已完成/已作废必须关联商务谈判或赢单商机；审批后金额锁定；变更走子流程留痕
回款计划中 → 待回款 → 部分回款/逾期 → 已回款 → 已核销财务确认到账；先到期先核销；核销不可改、红冲需财务权限；全核销后合同自动完成

6. 数据权限设计（角色 × 数据范围 × 操作项）

6.1 权限模型

模型公式：权限判定 = f(功能权限[角色], 数据范围[角色], 字段权限[角色×字段])。数据范围在数据访问层（SQL）过滤，而非前端隐藏；全部越权尝试写入审计日志。
SELF : owner_id = current_user OR current_user ∈ collaborators
TEAM : owner.dept_id ∈ current_user.dept 子树（含下级）
REGION : owner.dept_id ∈ current_user.region 子树（区域组织树全节点）
POOL : owner_id IS NULL（公海，领取受冷却期/上限约束）

6.3 特殊规则

  • 协作机制：owner 可邀请协作人（读写）与只读成员，协作人获得该记录 SELF 级访问；
  • 撞单仲裁：跨团队重复客户由区域总监仲裁归属，仲裁记录不可撤销；
  • 离职交接：一键转移名下全部数据，转移后原账号数据范围立即回收。

7. 客户全生命周期指标方案

7.1 指标体系总览

按生命周期分四层：获客层（线索）→ 转化层（商机）→ 履约层（合同）→ 回款层（资金），共 10 项核心指标，每项含口径、公式、阈值与责任角色。

层级指标计算公式健康阈值责任角色
获客层① 线索转化率已转化线索数 ÷ 有效线索总数（按渠道下钻）≥ 20%市场/销售
② 线索首访及时率24h 内完成首访线索数 ÷ 分配线索总数≥ 95%销售
③ 公海流转率周期内掉入公海线索数 ÷ 在管线索总数10%-25%（过低=私藏，过高=质量差）销售主管
转化层④ 赢单率赢单商机数 ÷ 关单商机数（赢单+输单）≥ 30%销售主管
⑤ 赢单周期Σ(赢单关单日 − 商机创建日) ÷ 赢单数，同时输出 P50/P90P50 ≤ 45 天销售主管
⑥ 阶段转化率进入下一阶段商机数 ÷ 进入本阶段商机数（逐阶段）每级 ≥ 50%销售主管
⑦ 跟进及时率按规则准时跟进次数 ÷ 应跟进总次数（新增线索 24h；在谈商机 ≤7 天；成交客户 ≤30 天）≥ 92%销售/主管
履约层⑧ 合同平均审批时长Σ(审批通过时刻 − 提交时刻) ÷ 合同数≤ 48h主管/财务
回款层⑨ 回款达成率实际核销回款额 ÷ 计划回款额（本期）≥ 90%财务/主管
⑩ 回款周期 DSOΣ(核销日 − 合同签订日) ÷ 合同数（或应收账款周转口径）≤ 45 天财务

7.2 三个重点指标的落地细节

① 线索转化率

  • 口径：分子=状态变更为「已转化」的线索；分母=剔除「无效且 24h 内判定」后的线索（避免垃圾数据稀释）；
  • 下钻维度：渠道 → 行业 → 区域 → 个人；支撑「渠道 ROI 排序」决策；
  • 看板：工作台 KPI 卡（本人）/ 主管驾驶舱（团队对比渠道柱状图）；
  • 预警：单渠道转化率连续 2 周 < 10% 时通知市场负责人。

⑤ 赢单周期

  • 口径：赢单商机关单日 − 创建日；同时统计各阶段停留时长定位瓶颈；
  • 分位值：P50/P90 双值展示，避免均值被极端值扭曲；
  • 关联动作：与「阶段停留阈值」联动，超 P75 分位自动标记黄色风险；
  • 复盘：季度输出「周期 vs 赢单率」散点，识别高耗低效商机模式。

⑦ 跟进及时率

  • 口径：系统按三条规则生成「应跟进」任务（24h 首访 / 7 天商机 / 30 天成交客户），在截止前完成有效跟进（电话/拜访/有效沟通记录）计 1 次；
  • 红线：92%（低于即触发主管周报点评）；个人连续 2 周 < 80% 进入主管重点关注名单；
  • 反作弊：跟进记录需含摘要 ≥ 10 字或外勤签到凭证，纯点击不计。

7.3 数据采集与计算

链路：业务库 binlog → 数仓 ODS → DWD 明细（事件：clue_created / followup_done / stage_changed / payment_verified）→ DWS 日汇总 → 指标服务 T+1 06:00 批算 → 看板/预警
  • 指标全部可追溯到事件表，支持自定义时间窗对比（周/月/季环比）；
  • 角色数据范围同样作用于指标：销售看本人、主管看团队、总监看区域汇总。

阶段内容出口标准
