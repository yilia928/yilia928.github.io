项目二 · B 端核心链路逆向设计

CRM 客户与商机管理后台 · 逆向产品设计

以纷享销客、销售易两款主流 CRM SaaS 为参照对象，逆向拆解「线索 → 商机 → 合同 → 回款」客户管理主链路，跑通业务建模 → 数据权限 → 原型 → PRD → 指标方案的 B 端产品完整交付流程。

4 套交付物（建模图 / 原型 / PRD / 权限矩阵） 28 项角色 × 数据范围 × 操作项矩阵 10 页高保真原型 10 项全生命周期指标

为什么做逆向设计

CRM 是 B 端产品里最成熟、也最能体现「流程 + 权限 + 指标」基本功的品类。与其凭空设计，不如把成熟产品的主链路逐节点还原，理解每个规则为什么存在，再做出自己的取舍——这比照着竞品抄功能更能检验产品设计能力。

方法：把纷享销客与销售易按同一框架（流程体系 / 公海规则 / 商机管理 / 权限体系）横向拆解，逐项记录两者做法的差异，再决定本项目取谁、舍谁、为什么。

由此沉淀四条设计原则：先流程后功能（所有页面挂在 LTC 主流程节点上，无孤立功能）、录入减负（查重前置、线索 4 个必填字段即可创建）、过程数据资产化（每次跟进自动沉淀时间线）、权限即数据（数据范围在 SQL 层过滤，而非前端隐藏）。

主流程与状态流转

线索获取与查重→ 分配 / 领取→ 跟进验证→ 转化（客户 + 商机）→ 阶段推进（门禁）→ 报价 / 合同审批→ 签订生成回款计划→ 回款核销

四个对象各有严格的状态机，几条关键规则：

  • 线索：24h 首访红线；7 天未跟进自动掉公海；无效为终态且必填原因；转化在事务内原子生成客户 + 商机；
  • 商机：五阶段各带赢率（15% / 30% / 45% / 75%），推进需过门禁校验（POC、报价单等），反向回退需审批，停留超时自动告警，加权预测 = 金额 × 赢率；
  • 合同：必须关联赢单商机；审批通过后金额锁定，变更走子流程留痕；
  • 回款：财务确认到账后按「先到期先核销」自动核销，核销不可改、红冲需财务权限，全部核销后合同自动完成。

数据权限：销售 / 销售主管 / 区域总监

权限判定 = f(功能权限[角色], 数据范围[角色], 字段权限[角色 × 字段])。数据范围在数据访问层（SQL）过滤，而非前端隐藏；全部越权尝试写入审计日志。数据范围口径：SELF（本人 + 协作人）/ TEAM（部门子树）/ REGION（区域组织树全节点）/ POOL（公海，领取受冷却期与上限约束）。

客户全生命周期指标方案

按生命周期分四层共 10 项指标，每项含口径、公式、健康阈值与责任角色，取其中三个重点说明落地深度。
获客层 · 线索→ 转化层 · 商机→ 履约层 · 合同→ 回款层 · 资金
  • 线索转化率（≥20%）：分子只算状态变更为「已转化」的线索，分母剔除「无效且 24h 内判定」的部分，避免垃圾数据稀释；支持渠道 → 行业 → 区域 → 个人下钻，单渠道连续 2 周 <10% 自动通知市场负责人；
  • 赢单周期（P50 ≤ 45 天）：同时输出 P50 / P90 双分位值避免均值被极端值扭曲；与阶段停留阈值联动，超 P75 分位自动标记黄色风险；季度输出「周期 vs 赢单率」散点识别高耗低效商机模式；
  • 跟进及时率（≥92%）：系统按三条规则生成「应跟进」任务（新线索 24h / 在谈商机 7 天 / 成交客户 30 天），截止前完成有效跟进才计数；个人连续 2 周 <80% 进主管重点关注名单；跟进记录需含 10 字以上摘要或外勤签到凭证，纯点击不计——防作弊写进了口径。

计算链路：业务库 binlog → 数仓 ODS/DWD（事件表：clue_created / followup_done / stage_changed / payment_verified）→ DWS 日汇总 → T+1 06:00 批算 → 看板与预警。指标可追溯到事件表，且角色的数据范围同样作用于指标。
