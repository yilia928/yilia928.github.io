项目三 · SQL 数据分析

SaaS 产品功能使用与留存分析

基于 SaaS 用户行为数据集（5,000 名注册用户 / 46,549 条行为事件），用 SQL 完成激活漏斗、功能使用频次、次月留存与流失定位四类分析，定位流失最严重的环节，并给出带依据和预期收益的产品改进建议。

43.7%整体激活率 63.0%最薄弱环节步间转化 2.5×激活用户留存倍数 4 组SQL 脚本可复现

分析链路

SQLite 建库 → 四组 SQL → 结果导出，全链路脚本化可复现（接入真实数据只需替换 users / events 两张 CSV，SQL 无需改动）。
  • 00 建表装载：用户维表（注册日期 / 渠道 / 套餐）+ 行为事件表（signup / login / create_project / invite_member / generate_report / export_data / dashboard_view）；
  • 01 激活漏斗：注册 → 首次登录 → 创建首个项目 → 邀请协作者 → 生成首份报表，按事件日期先后判定顺序；
  • 02 功能使用频次：总量 / 人均 / 使用深度分桶；
  • 03 次月留存：注册月同期群 / 分渠道 / 激活与否对比；
  • 04 流失定位：渠道 × 套餐的步间转化率交叉定位。

全部指标口径（含事件字典与判定规则）单独成文，先定口径再跑数——这是这份分析里我刻意保持的习惯。

流失最严重的环节是「首次登录 → 创建首个项目」：4,742 名登录用户中只有 2,989 人创建项目，单步流失 1,753 人，占总注册用户的 35.1%。后面的邀请（82.3%）和报表（88.9%）两步都健康——用户能顺利登录，却迈不过「从观看到动手」这一步，是整体激活率只有 43.7% 的主要瓶颈。

发现二：流失集中在 SEM 渠道，是流量质量 × 引导的叠加

把「创建首个项目」的步间转化按渠道 × 套餐交叉切分：SEM 投放渠道三个套餐全部低于 55%（48.8% ~ 54.1%），而内容营销与线下活动均在 68% 以上。SEM 贡献了 27.6% 的注册量，付费流量意图偏浅，和产品核心工作流匹配度低。

发现三：激活是留存的第一分水岭，但激活后的深度不够

  • 激活用户次月留存 59.7%，未激活用户仅 23.7%，相差 35.9 个百分点——把用户推进漏斗最后一格，是提升留存杠杆最大的动作；
  • 激活用户人均 16.1 次事件，是未激活用户（4.0 次）的 4 倍，功能使用与激活强相关；
  • 但 56.4% 的激活用户-月每月只生成 1 份报表，每月 7 次以上的重度使用几乎不存在——激活之后的使用深度普遍偏浅，报表还没变成周期性工作习惯；
  • 渠道留存排序：老客推荐 49.0% > 内容营销 44.6% > 线下活动 41.8% > 自然流量 37.2% > SEM 33.0%，与漏斗表现相互印证。

改进建议（每条带口径依据与预期收益）

  • 重构新手引导：把「创建首个项目」做成注册后的强制主线任务，提供 2–3 个行业模板一键创建替代空白页，48 小时内用引导清单 + 邮件 / Push 召回未创建用户。依据：漏斗第三步流失 1,753 人；预期：该步转化 63% → 75%，整体激活率约 43.7% → 52%；
  • SEM 渠道独立落地页与激活路径：落地页与广告承诺的场景对齐、注册后预填场景化模板，同时给 SEM 设激活率考核，必要时下调低质词组预算。依据：SEM 创建项目转化 48.8%~54.1%、留存 33.0% 垫底；
  • 「邀请协作者」从串行阻塞改为并行增强：允许跳过邀请直接生成首份报表（用模板示例数据演示核心价值），创建项目后再即时推荐邀请。依据：④→⑤ 的串行依赖拖慢价值到达，而激活与留存强相关；
  • 激活后 7 日习惯养成：首份报表后引导「定时报表 / 订阅推送」，对连续 2 周未再生成报表的激活用户用深度功能召回。依据：56.4% 的用户-月仅 1 份报表；
  • 放大老客推荐，把「7 日激活率」设为共同北极星：上线双边激励的邀请计划，按本报告口径建立周度看板。依据：老客推荐留存最高（49.0%）但仅占注册量 12.6%。
